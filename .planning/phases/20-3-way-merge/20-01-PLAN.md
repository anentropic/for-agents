When USER differs from BASE AND BASE differs from NEW (the user customized the file AND the plugin updated it):

**Section parsing rules** (include these once, reference from both 2-way and 3-way paths):

Instruct Claude to parse the file content into sections:
1. **Preamble**: Everything from the start of the file up to (but not including) the first line that starts with `## `. If no `## ` line exists, the entire file is the preamble. Identify as `__preamble__`.
2. **Named sections**: Each line starting with `## ` (at document top level, NOT inside a fenced code block) begins a new section. The section includes the heading line and all content up to the next `## ` heading or end of file.
3. **Sub-headings are NOT section boundaries**: Lines starting with `### ` or `#### ` are part of their parent `## ` section.
4. **Code block awareness**: Track whether you are inside a fenced code block (between ``` delimiters). Skip any `## ` that appears within a fenced code block.
5. **Comparison**: When comparing two sections for equality, compare after trimming trailing whitespace from each line and normalizing trailing newlines. Semantic comparison, not byte-exact.

**3-way classification table** (encode this full decision table in the SKILL.md prose):

| In BASE? | In USER? | In NEW? | BASE==USER? | BASE==NEW? | USER==NEW? | Classification | Action |
|----------|----------|---------|-------------|------------|------------|----------------|--------|
| Y | Y | Y | Y | Y | - | Unchanged | Keep as-is |
| Y | Y | Y | Y | N | - | Upstream only | Auto-apply NEW |
| Y | Y | Y | N | Y | - | User only | Keep USER |
| Y | Y | Y | N | N | Y | Convergent | Keep USER |
| Y | Y | Y | N | N | N | **Conflict** | Ask user |
| N | N | Y | - | - | - | Added upstream | Auto-add from NEW |
| Y | Y | N | Y | - | - | Removed upstream (user didn't customize) | Auto-remove |
| Y | Y | N | N | - | - | **Conflict** (user customized, upstream removed) | Ask user: "Section '{heading}' was removed in the plugin update, but you have customized it." Options: "Remove it", "Keep mine", "Chat about this" |
| Y | N | Y | - | - | - | User removed | Keep removed |
| Y | N | N | - | - | - | Both removed | Already gone |
| N | Y | N | - | - | - | User added | Keep USER |
| N | Y | Y | - | - | Y | Both added (same) | Keep USER |
| N | Y | Y | - | - | N | **Conflict** (both added differently) | Ask user |

**Conflict resolution** (MERGE-03) -- for each conflict, present one at a time via AskUserQuestion:
- header: "Merge Conflict"
- question: "Section '{heading}' in {filename} was changed both by you and in the plugin update.\n\nYour version:\n---\n{first 10 lines of USER section, or full if <= 10 lines}\n{if truncated: '... **Section ordering in merged output:**
1. Preamble always first
2. Sections present in NEW define the canonical order
3. User-added sections (in USER but not in NEW or BASE) appended after the last NEW section, preserving their relative order from USER
