**CRITICAL: Do NOT duplicate diataxis or humanizer mandates.** The doc-writer agent prompts already enforce these. This file focuses on OCaml/odoc-specific preferences only.

**Opening paragraph:**
```
# Odoc Guidance

Opinionated preferences for writing documentation with odoc for OCaml libraries. These are style preferences -- agents already understand odoc syntax. This file guides how features should be used, not what they are.
```

**Section 1: Code Blocks**
- `{[ ... ]}` for OCaml code -- compiled by odoc, must be syntactically valid
- `{v ... v}` for verbatim/raw text -- no syntax highlighting, no compilation
- `{@lang[ ... ]}` for non-OCaml code (odoc 2.2+) -- syntax-highlighted, not compiled
- Show result types and values as comments in examples: `(* val size : int = 4096 *)`
- `{[ ... ]}` and `{v ... v}` blocks must start at column 0 in .mli comments (no leading indentation)
- Use `let () = expr` after `let` bindings in `{[ ... ]}` blocks, not bare expressions
- Include concrete examples from SKILL.md Core Principles section

**Section 2: .mld File Structure**
- Heading levels: `{0 Page Title}` for page title (only in .mld), `{1 Section}`, `{2 Subsection}`
- In .mli comments, headings start at `{1 ...}` (not `{0 ...}`)
- Page title format: `{0 Package_name - Brief description}`
- Filename rules: underscores ONLY (never hyphens) -- `getting_started.mld` works, `getting-started.mld` breaks `{!page-...}` references
- Every new .mld file MUST be registered in the `(mld_files ...)` list in the corresponding `doc/dune` -- unregistered files silently do not appear in generated docs
- Include the file structure diagram from SKILL.md

**Section 3: .mli Doc Comments**
- Function docs: summary line, extended description, `{[ ... ]}` examples, `@param`, `@return`, `@raise`
- Module-level doc comment: `(** ... *)` before the first declaration
- Show the function doc example from SKILL.md (Duration.of_string with multiple {[ ]} blocks)
- Show the module doc comment example from SKILL.md (frontmatter pattern)
- Add comments for public values that have none; preserve existing comments; do not rewrite what the maintainer already wrote unless clearly incorrect (per CONTEXT.md locked decision)

**Section 4: Cross-References**
Absorb the full cross-reference table from SKILL.md and CROSS_PACKAGE.md:
- Within-package module refs: `{!Module.value}`, `{!Module.Type}`, `{!module:Module}`, `{!module-type:S}`
- Within-package page refs: `{!page-guide_name}`
- Cross-package links: `{{:../other_package/page.html} text}` (HTML URLs required)
- Cross-package module links: `{{:../other_package/Module/index.html} text}`
- External URLs: `{{:https://example.com} text}`
- Section refs: `{!section-anchor_name}` with `{1:anchor_name Title}`
- CRITICAL pitfall: `{!page-name}` only resolves within the same package. Cross-package links MUST use relative HTML URLs.
- CRITICAL pitfall: HTML output is `getting_started.html`, NOT `page-getting_started.html` (no `page-` prefix)

**Section 5: File Naming**
- Underscores only, never hyphens
- HTML output filename = .mld filename with .html extension (no prefix)
- Explain WHY hyphens break: odoc parses `{!page-getting-started}` as qualifier `page-getting` + target `-started`
- Include the examples from SKILL.md Critical odoc Gotchas

**Section 6: Dune Wiring**
- `(documentation (package name) (mld_files ...))` stanza goes in `doc/dune` (NOT `lib/dune`)
- The `(documentation ...)` stanza only picks up .mld files from its own directory
- `(odoc :with-doc)` must be in dune-project package deps
- Root `dune` must include `doc` in `(dirs ...)` if it uses `(dirs ...)`
- When creating a new .mld file, ALWAYS add it to `(mld_files ...)` -- unregistered files silently do not appear
- Include the dune configuration examples from SKILL.md Setup Checklist

**Section 7: Multi-Package Documentation**
Absorb the full multi-package architecture from CROSS_PACKAGE.md:
- Only the primary package gets full documentation (tutorials, how-tos, explanations)
- Secondary packages get brief overview .mld + API reference + cross-links back to primary
- Each package's .mld files live in `doc/{package_name}/dune` (except primary which uses `doc/dune`)
- Dune configuration examples for primary and secondary packages (from CROSS_PACKAGE.md)
- Cross-package link syntax (from CROSS_PACKAGE.md)
- HTML directory layout showing the generated structure
- Diataxis mapping table: tutorials/how-tos/explanations in primary only; reference (.mli) in all; overview (index.mld) in all

**Section 8: Build Validation**
- `dune build @doc` is the standard build target -- run as final check after writing
- Catches: broken cross-references, invalid .mld syntax, missing dune registrations, bad OCaml code blocks
- `open _build/default/_doc/_html/index.html` to review generated docs
- Common error patterns and what they mean

**Section 9: odoc 3.x Preview** (forward-looking, brief)
- Note that odoc 3.0/3.1 exists on opam but dune has not updated its build rules
- New features available in odoc 3.x: tables with `{t ...}`, media with `{image:...}`, `{@lang[ ... ]}` language blocks, `odoc-config.sexp` for cross-package configuration
- Do NOT use odoc 3.x-only syntax in any templates or examples -- `dune build @doc` uses odoc 2.x rules

**Section 10: Quality Checklist**
Absorb and adapt the quality checklist from SKILL.md (remove diataxis/humanizer items since those are enforced by the agent prompts):
```markdown
- [ ] Main .mli has module-level doc comment (from README if available)
- [ ] Each library has an .mld overview page (index.mld)
- [ ] 90%+ of public functions have usage examples
- [ ] Examples show result types/values as comments
- [ ] `dune build @doc` passes with zero warnings
- [ ] Cross-package links use HTML URLs, not `{!page-...}`
- [ ] .mld filenames use underscores, not hyphens
- [ ] Every .mld file registered in `(mld_files ...)` in its doc/dune
- [ ] Top-level pages link to GitHub repository
- [ ] Generated HTML reviewed for navigation and broken links
```
