2. **`skills/quality-rules/SKILL.md`** — Universal quality rules skill. Frontmatter:
```yaml
---
name: quality-rules
description: Universal documentation quality rules applied by all doc-writer agents. Non-overridable baseline standards.
user-invocable: false
---
```

Body must contain these 5 rules (taken from RESEARCH.md, verified against REQUIREMENTS.md):
- **Rule 1: No Internal Details** — Docs must never reference test utilities, CI/CD config, dev scripts, justfile recipes, internal module names not part of public API, maintainer-only concerns.
- **Rule 2: Working Code Examples Required** — Every documented API feature/function must include at least one realistic, working code example. Examples must demonstrate real use cases, include enough context for understanding, and specify language in fenced code blocks.
- **Rule 3: Consistent Structure** — All pages of the same doc type (tutorial, how-to, reference, explanation) must follow the same structural template.
- **Rule 4: Cross-Reference Code Mentions** — All inline `code` mentions in prose must be linked to the relevant API Reference entry where one exists.
- **Rule 5: Audience-Calibrated Language** — Vocabulary, assumed knowledge, and explanation depth must match the configured audience. Never assume knowledge listed in the audience's `never_assume` list.

Each rule should have a brief explanation paragraph (3-5 sentences) explaining the "why" and what violation looks like.

3. **`skills/diataxis/SKILL.md`** — Diataxis framework reference. Frontmatter:
```yaml
---
name: diataxis
description: Diataxis content classification and structural templates for documentation pages.
user-invocable: false
---
```

Body defines the 4 diataxis content types with structural templates:
- **Tutorial**: Learning-oriented. Sections: Introduction (what you will build), Prerequisites, Steps (numbered, each with explanation), What You Learned, Next Steps.
- **How-To Guide**: Task-oriented. Sections: Goal statement, Prerequisites, Steps (focused, minimal explanation), Troubleshooting (common issues).
- **Reference**: Information-oriented. Sections: Synopsis, Parameters/Arguments (table format), Return Value, Examples, Related.
- **Explanation**: Understanding-oriented. Sections: Context (why this matters), Concept (the idea), How It Works, Tradeoffs/Alternatives, Further Reading.

For each type, include: when to use it, what makes it different from the others, and the structural template as a markdown outline.
